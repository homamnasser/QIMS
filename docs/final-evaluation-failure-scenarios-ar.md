# مرجع سيناريوهات فشل التقييم النهائي ومعالجة الأخطاء

**المشروع:** QIMS
**النطاق:** دورة التقييم النهائي كاملة، من إنشاء الدورة حتى إصدار الشهادة والتحقق منها.
**الغرض:** هذا المستند هو المرجع الأول عند السؤال «لماذا لم يكتمل التقييم النهائي؟». يحصر كل حالة تمنع إتمام العملية، ويحدد لكل حالة: سببها، ورمز حالة HTTP، ورمز الخطأ، والرسالة التي يراها المستخدم، وموضع معالجتها في الشيفرة، وطريقة الحل.

**مراجع مكملة:**

- `docs/final-evaluation-reference-ar.md` — المرجع التنفيذي لقواعد الاحتساب.
- `docs/final-evaluation-e2e-scenario-ar.md` — سيناريو تشغيلي كامل من البداية إلى النهاية.

---

## 1. الخلاصة التنفيذية

نظام التقييم النهائي يمنع النتيجة الرسمية عمدًا كلما كانت البيانات ناقصة أو الحالة غير مناسبة. لذلك معظم حالات «التقييم لا يكتمل» ليست أعطالًا، بل حواجز مقصودة. ينقسم ما يمنع الإتمام إلى ست عائلات:

| # | العائلة | رمز HTTP | من يعالجها | الطبيعة |
|---|---------|----------|------------|---------|
| 1 | فشل التحقق من المدخلات | 422 | `Illuminate\Validation` + `lang/ar/validation.php` | خطأ مستخدم، قابل للإصلاح فورًا |
| 2 | خطأ منطق العمل (حالة أو ترتيب خاطئ) | 422 | خدمات `App\Services\Evaluation\*` | خطأ إجرائي، يحتاج خطوة سابقة |
| 3 | نقص الصلاحية أو النطاق | 403 | `EvaluationAccessService` + `permission` middleware | خطأ صلاحيات |
| 4 | مورد غير موجود أو غير مرئي | 404 | ربط النماذج في المسار + `Handler` | خطأ مرجع |
| 5 | تعارض مع الحالة الحالية | 409 / 410 | المتحكمات و`CertificateService` | خطأ تزامن أو سجل ملغى |
| 6 | خطأ قاعدة بيانات أو خطأ غير متوقع | 500 / 503 | `App\Exceptions\Handler` | عطل فني، يُسجَّل ولا يُعرض |

القاعدة الحاكمة: **لا يخرج إلى الواجهة أي نص SQL، أو اسم موديل، أو أثر استدعاء (stack trace)، أو رسالة إطار إنجليزية.** التفاصيل الفنية الكاملة تبقى في سجل الخادم.

## 2. العقد الموحد لاستجابات الخطأ

### 2.1 شكل الاستجابة

كل خطأ يصدر عن أي مسار تحت `/api/*` يعود بالشكل نفسه:

```json
{
  "code": 422,
  "error_code": "VALIDATION_FAILED",
  "message": "حقل درجة السلوك مطلوب.",
  "errors": { "behavior_score": ["حقل درجة السلوك مطلوب."] },
  "data": null
}
```

| الحقل | متى يوجد | الاستخدام في الواجهة |
|-------|-----------|------------------------|
| `code` | دائمًا | يطابق رمز حالة HTTP، لتسهيل التسجيل والتشخيص |
| `error_code` | دائمًا | مفتاح ثابت غير مترجم؛ عليه تُبنى المعالجة البرمجية لا على نص الرسالة |
| `message` | دائمًا | جملة عربية واحدة تُعرض للمستخدم مباشرة |
| `errors` | في 422 فقط | خريطة `{الحقل: [رسائل]}` تُعرض أسفل كل مدخل في النموذج |
| `data` | دائمًا (قد تكون `null`) | حمولة مساعدة، مثل لقطة الجاهزية أو عدد السجلات المانعة |
| `debug` | في بيئة التطوير فقط (`APP_DEBUG=true`) | صنف الاستثناء ورسالته وموضعه؛ لا يُعرض للمستخدم أبدًا |

**نقطة جوهرية:** حقل `errors` مخصص حصريًا لأخطاء الحقول التي تُعرض أسفل المدخلات. أي حمولة منظمة أخرى — كلقطة الجاهزية — تُعاد في `data`، وليس في `errors`.

### 2.2 جدول رموز الأخطاء

| `error_code` | HTTP | متى يصدر |
|--------------|------|-----------|
| `VALIDATION_FAILED` | 422 | فشل قاعدة تحقق أو قاعدة عمل تُرمى عبر `ValidationException` |
| `CYCLE_NOT_READY` | 422 | محاولة إغلاق جمع البيانات أو الاحتساب النهائي قبل اكتمال المدخلات |
| `NO_PUBLISHED_RESULTS` | 422 | إصدار شهادات لتشغيل لا يحتوي نتائج منشورة |
| `UNAUTHENTICATED` | 401 | لا توجد جلسة أو رمز دخول صالح |
| `FORBIDDEN` | 403 | الصلاحية أو النطاق لا يسمح بالإجراء |
| `NOT_FOUND` | 404 | المورد غير موجود، أو موجود لكنه خارج نطاق المستخدم |
| `METHOD_NOT_ALLOWED` | 405 | طريقة HTTP غير مدعومة للمسار |
| `CONFLICT` | 409 | تعارض مع الحالة الحالية، مثل ملف شهادة لا يطابق بصمته |
| `GONE` | 410 | الشهادة ملغاة أو استُبدلت بإصدار أحدث |
| `SESSION_EXPIRED` | 419 | انتهت صلاحية رمز CSRF أو الجلسة |
| `TOO_MANY_REQUESTS` | 429 | تجاوز حد المحاولات |
| `DATABASE_ERROR` | 500 | فشل استعلام قاعدة بيانات |
| `SERVER_ERROR` | 500 | خطأ برمجي غير متوقع |
| `SERVICE_UNAVAILABLE` | 503 | خدمة خارجية معطلة، مثل محرك توليد الشهادات |

### 2.3 موضع التنفيذ

- `app/Exceptions/Handler.php` — المعالج المركزي. يحوّل كل استثناء إلى الشكل أعلاه، ويستبدل رسائل الإطار الإنجليزية برسائل عربية، ويسجل التفاصيل الفنية.
- `lang/ar/validation.php` — ترجمة كل قواعد التحقق، إضافة إلى قسم `attributes` الذي يستبدل اسم الحقل البرمجي باسمه العربي.
- `lang/ar/auth.php` — رسائل المصادقة.
- `config/app.php` — `locale` أصبح `ar` مع بقاء `fallback_locale` على `en`.

**آلية منع تسرب الرسائل الإنجليزية:** استثناء HTTP يُعرض بالرسالة المرفقة به فقط إذا كانت مكتوبة بالعربية عمدًا (`abort(410, 'رسالة')`). أما رسائل الإطار الافتراضية — ومنها `No query results for model [App\Models\EvaluationCandidate] 42` التي تكشف أسماء الموديلات — فتُستبدل تلقائيًا بالرسالة العربية المقابلة لرمز الحالة.

## 3. مسار التقييم ونقاط التوقف

```text
إنشاء الدورة (draft)
   └─ مزامنة المرشحين
        └─ بدء جمع البيانات (data_collection)
             └─ إدخال تقييم المدرس + تأكيد القرآن + اعتماد الحسم الإداري
                  └─ فحص الجاهزية
                       └─ إغلاق جمع البيانات (ready)
                            └─ الاحتساب النهائي (calculated)
                                 └─ الاعتماد (approved) + إنشاء قائمة التكريم
                                      └─ النشر (published)
                                           └─ إصدار الشهادات
                                                └─ التنزيل والتحقق
```

كل سهم في المخطط أعلاه هو نقطة توقف محتملة. الأقسام التالية تغطيها بالترتيب نفسه.

## 4. المرحلة 1: إنشاء دورة التقييم

**المسار:** `POST /api/evaluation-cycles`
**الصلاحية:** `إدارة دورات التقييم`
**الشيفرة:** `EvaluationCycleController::store` → `EvaluationCycleService::create`

### 4.1 فشل التحقق من المدخلات

| السبب | الحقل | الرسالة | HTTP |
|-------|-------|---------|------|
| لم يُختر مشروع | `project_id` | حقل المشروع مطلوب. | 422 |
| المشروع المختار محذوف أو غير موجود | `project_id` | قيمة المشروع المختارة غير موجودة في النظام. | 422 |
| اسم الدورة فارغ | `name` | حقل الاسم مطلوب. | 422 |
| اسم الدورة أطول من 255 حرفًا | `name` | يجب ألا يتجاوز طول الاسم 255 حرفًا. | 422 |
| موسم غير معروف | `season` | قيمة الموسم المختارة غير مسموح بها. | 422 |
| عدد المكرمين خارج المدى 1–100 | `top_students_count` | يجب ألا تقل قيمة عدد الطلاب المكرمين عن 1. | 422 |
| لم يُختر أي مقرر | `course_ids` | يجب اختيار مقرر واحد على الأقل لدورة التقييم. | 422 |
| مقرر مكرر في القائمة | `course_ids.*` | يحتوي المقرر على قيمة مكررة. | 422 |
| لم تُعرَّف أي فترة | `periods` | يجب تعريف فترة تقييم واحدة على الأقل. | 422 |
| ترتيب فترة مكرر | `periods.*.sequence` | يحتوي ترتيب الفترة على قيمة مكررة. | 422 |
| تاريخ فترة غير صالح | `periods.*.start_date` | يجب إدخال تاريخ صالح في حقل تاريخ بداية الفترة. | 422 |

**الحل:** إصلاح الحقل المميز في النموذج. الواجهة تعرض كل رسالة أسفل مدخلها، وتنقل المستخدم تلقائيًا إلى أول خطوة تحتوي خطأ.

### 4.2 أخطاء منطق العمل

| السيناريو | الرسالة | الشيفرة |
|-----------|---------|---------|
| مقرر مختار لا يتبع المشروع نفسه، أو أحد المعرفات غير موجود | كل المقررات المختارة يجب أن تنتمي إلى المشروع نفسه. | `EvaluationCycleService::create` |
| نهاية الفترة قبل بدايتها | الفترة رقم N: يجب أن تكون نهاية الفترة مساوية لبدايتها أو لاحقة لها. | `EvaluationCycleService::validatePeriods` |
| فترتان متداخلتان زمنيًا | الفترة رقم N: فترات التقييم يجب ألا تتداخل. | `EvaluationCycleService::validatePeriods` |

**ملاحظة:** الفترات تُرتَّب حسب `sequence` قبل الفحص، لذلك التداخل يُكتشف بترتيب الفترات المنطقي لا بترتيب إرسالها.

### 4.3 خطأ الصلاحية

| السيناريو | HTTP | الرسالة |
|-----------|------|---------|
| المستخدم لا يملك صلاحية `إدارة دورات التقييم` | 403 | ممنوع: لا تملك الصلاحيات المطلوبة للوصول. |
| المستخدم يملك الصلاحية لكنه ليس مشرف المشروع ولا مشرف عمليات ميداني ولا مدير النظام | 403 | ممنوع: لا تملك الصلاحيات المطلوبة لتنفيذ هذا الإجراء. |

**التمييز مهم:** الحالة الأولى يمنعها `permission` middleware، والثانية يمنعها `EvaluationAccessService::canConfigureProject`. الحل مختلف: الأولى تحتاج تعديل الدور، والثانية تحتاج تعيين المستخدم مشرفًا للمشروع.

## 5. المرحلة 2: مزامنة المرشحين

**المسار:** `POST /api/evaluation-cycles/{cycle}/sync-candidates`
**الشيفرة:** `EvaluationCandidateSyncService::sync`

| السيناريو | HTTP | الرسالة | الحل |
|-----------|------|---------|------|
| حالة الدورة ليست `draft` ولا `data_collection` | 422 | لا يمكن مزامنة المرشحين بعد إغلاق مرحلة جمع البيانات. | أعد الدورة إلى `data_collection` قبل المزامنة |
| لا مقرر مرتبط بالدورة | 422 | يجب ربط مقرر واحد على الأقل بدورة التقييم. | اربط مقررات الدورة |
| المستخدم لا يدير الدورة | 403 | ممنوع: لا تملك الصلاحيات المطلوبة لتنفيذ هذا الإجراء. | يجب أن يكون مشرف المشروع أو مشرف أحد مقرراته |
| معرف دورة غير موجود | 404 | العنصر المطلوب غير موجود أو غير متاح لك. | تحقق من الرابط |

### 5.1 حالات صامتة لا تُصدر خطأ

هذه الحالات تُنجح الطلب لكنها تُنقص النتيجة، وهي من أكثر أسباب «التقييم ناقص ولا أرى خطأ»:

| الحالة | الأثر | كيف تُكتشف |
|--------|-------|-------------|
| تسجيل طالب بلا سجل طالب مرتبط | يُتخطى بصمت | العدد المعاد في `data.candidates` أقل من المتوقع |
| حلقة بلا مقرر مرتبط | تُتخطى بصمت | العدد المعاد في `data.enrollments` أقل من المتوقع |
| طالب انضم بعد المزامنة | لا يظهر في المرشحين | أعد المزامنة قبل إغلاق جمع البيانات |
| طالب غادر بعد المزامنة | يبقى مرشحًا نشطًا | يبقى مطلوبًا في فحص الجاهزية وقد يمنع الاحتساب |

**التوصية:** بعد كل مزامنة، قارن `data.candidates` بعدد الطلاب المتوقع. الفرق يعني سجلات تشغيلية ناقصة الربط.

## 6. المرحلة 3: بدء جمع البيانات وإغلاقه

**المسار:** `PUT /api/evaluation-cycles/{cycle}/status`
**الشيفرة:** `EvaluationCycleController::transition` → `EvaluationCycleService::transition`

### 6.1 الانتقالات المسموحة

| من | إلى المسموح |
|----|--------------|
| `draft` | `data_collection` |
| `data_collection` | `ready`، `draft` |
| `ready` | `data_collection` |

أي انتقال آخر مرفوض. الحالات `calculated` و`approved` و`published` لا تملك انتقالًا يدويًا للخلف عبر هذا المسار.

### 6.2 حالات الفشل

| السيناريو | HTTP | `error_code` | الرسالة |
|-----------|------|--------------|---------|
| حالة مطلوبة خارج `draft/data_collection/ready` | 422 | `VALIDATION_FAILED` | قيمة الحالة المختارة غير مسموح بها. |
| انتقال غير مسموح | 422 | `VALIDATION_FAILED` | لا يمكن نقل الدورة من حالة «محسوبة» إلى حالة «جاهزة». |
| بدء جمع البيانات قبل انتهاء آخر فترة | 422 | `VALIDATION_FAILED` | لا يبدأ التقييم إلا بعد انتهاء آخر فترة واكتمال أيام الدوام الفعلية. |
| إغلاق جمع البيانات والمدخلات ناقصة | 422 | `CYCLE_NOT_READY` | لا يمكن إغلاق جمع البيانات قبل اكتمال المدخلات: 12 من 40 طالب جاهز. |

**ملاحظة مهمة:** أسماء الحالات تظهر بالعربية داخل الرسالة («إعداد»، «جمع البيانات»، «جاهزة»، «محسوبة»، «معتمدة»، «منشورة»، «مؤرشفة»)، ولا تصل رموزها البرمجية إلى الواجهة.

**حالة `CYCLE_NOT_READY`** تعيد لقطة الجاهزية الكاملة في `data.readiness`، فتحدّث الواجهة لوحة الجاهزية فورًا لتُظهر الطلاب والمعايير الناقصة بالاسم. هذه اللقطة في `data` وليست في `errors`، لأنها ليست خطأ حقل.

## 7. المرحلة 4: إدخال بيانات التقييم

### 7.1 تقييم المدرس

**المسار:** `PUT /api/evaluation-candidates/{candidate}/teacher-evaluation`
(ونظيره في تطبيق الهاتف `PUT /api/mobile/teacher/evaluation-candidates/{candidate}/teacher-evaluation`)
**الشيفرة:** `EvaluationInputController::teacher` → `EvaluationInputService::saveTeacher`

| السيناريو | HTTP | الرسالة |
|-----------|------|---------|
| حقل درجة ناقص | 422 | حقل درجة السلوك مطلوب. |
| درجة غير رقمية | 422 | يجب إدخال رقم في حقل درجة السلوك. |
| حالة خارج `draft/submitted` | 422 | قيمة الحالة المختارة غير مسموح بها. |
| ملاحظات أطول من 3000 حرف | 422 | يجب ألا يتجاوز طول الملاحظات 3000 حرفًا. |
| درجة السلوك خارج 0–20 | 422 | درجة السلوك: يجب أن تكون القيمة بين 0 و20. |
| درجة المشاركة خارج 0–20 | 422 | درجة المشاركة والواجبات: يجب أن تكون القيمة بين 0 و20. |
| درجة رأي المدرس خارج 0–10 | 422 | درجة رأي المدرس: يجب أن تكون القيمة بين 0 و10. |
| الدورة تجاوزت مرحلة جمع البيانات | 422 | مدخلات التقييم مقفلة بعد انتهاء مرحلة جمع البيانات. |
| الفترة تتبع دورة أخرى | 422 | الفترة لا تتبع دورة تقييم الطالب. |
| الحلقة ليست ضمن تسجيل الطالب المجمد | 422 | الحلقة أو المقرر لا يتبع تسجيل الطالب المجمد في دورة التقييم. |
| المدرس ليس مدرس الحلقة ولا يدير الدورة | 403 | ممنوع: لا تملك الصلاحيات المطلوبة لتنفيذ هذا الإجراء. |
| معرف مرشح غير موجود | 404 | العنصر المطلوب غير موجود أو غير متاح لك. |

**الحدود القصوى للدرجات مأخوذة من لقطة السياسة المجمدة للدورة، لا من إعدادات النظام الحالية.** لذلك دورة قديمة تبقى محكومة بحدودها الأصلية بعد تغيير السياسة.

### 7.2 تأكيد حالة التسميع

**المسار:** `PUT /api/evaluation-candidates/{candidate}/quran-assessment`
**الشيفرة:** `EvaluationInputService::saveQuran`

المدخل اليدوي الوحيد هنا هو الإشارة `below_minimum`. أعداد الصفحات والمراجعة تُستخرج آليًا من `memorizations`.

| السيناريو | HTTP | الرسالة | التفسير |
|-----------|------|---------|---------|
| الحلقة لا تسمّع أصلًا (`quran_mode = none`)، أو لا أيام دوام فعلية في الفترة | 422 | معيار القرآن غير منطبق على هذه الحلقة أو لا توجد أيام دوام فعلية في الفترة. | الهدف المحسوب = صفر، فلا معنى للتقييم |
| الإنجاز أقل من الهدف بلا إشارة | 422 | يجب وضع إشارة «دون الحد الأدنى» عندما يكون الإنجاز أقل من الهدف. | يمنع مرور نقص غير موثق |
| بلوغ الهدف مع وضع الإشارة | 422 | لا يمكن وضع إشارة «دون الحد الأدنى» بعد بلوغ الهدف. | يمنع حسم درجة مستحقة |
| الدورة خارج مرحلة جمع البيانات | 422 | مدخلات التقييم مقفلة بعد انتهاء مرحلة جمع البيانات. | — |

### 7.3 اعتماد الحسم الإداري

**المسار:** `POST /api/administration-observations/{observation}/approve`

| السيناريو | HTTP | الرسالة |
|-----------|------|---------|
| الملاحظة ليست في حالة `pending` | 422 | يمكن اعتماد ملاحظة معلقة فقط. |
| المستخدم لا يدير الدورة | 403 | ممنوع: لا تملك الصلاحيات المطلوبة لتنفيذ هذا الإجراء. |

## 8. المرحلة 5: فحص الجاهزية — أكثر أسباب التعثر شيوعًا

**المسار:** `GET /api/evaluation-cycles/{cycle}/readiness`
**الشيفرة:** `EvaluationRunService::readiness` → `EvaluationCalculator::calculate`

الدورة جاهزة فقط إذا كان **كل** مرشح نشط جاهزًا، وكل معيار لديه حالته `ready` أو `not_applicable`. معيار واحد ناقص لطالب واحد يوقف الدورة كلها.

> **مصيدة متكررة:** إذا لم يكن في الدورة أي مرشح نشط، فالجاهزية `false` وليست `true`، لأن الشرط يتطلب وجود مرشحين. الرسالة تظهر «0 من 0 طالب جاهز»؛ الحل هو مزامنة المرشحين لا إعادة المحاولة.

### 8.1 معيار الحضور

| الحالة | `readiness_status` | التحذير |
|--------|--------------------|---------|
| لا جلسات محتسبة ضمن فترات الدورة | `missing` | لا توجد جلسات محتسبة للحضور ضمن دورة التقييم. |
| جلسة محتسبة بلا سجل حضور للطالب | `missing` | توجد جلسات بلا سجل حضور آلي؛ لا يجوز اعتماد النتيجة قبل اكتمالها. |

**السبب الجذري الأول:** لا توجد سجلات `course_dates` تحمل `counts_for_attendance = true` داخل نطاق فترات التقييم. الحل: إصلاح جدول أيام الدوام في نظام المقرر، لا في شاشة التقييم.

**السبب الجذري الثاني:** المصدر الخارجي — تطبيق الهاتف أو كاميرا التعرف على الوجه — لم يكتب سجلًا لجلسة معينة. الجلسات الناقصة مُعدَّدة بالتاريخ ورقم المقرر في `inputs.missing_sessions`، فتُعرف الجلسة المطلوب استكمالها بدقة.

**تحذير:** الحضور ليس مدخلًا يدويًا في شاشة التقييم. لا يمكن «تعبئة» جلسة ناقصة من واجهة التقييم؛ يجب إصلاحها في مصدرها.

### 8.2 معيار القراءة

| الحالة | `readiness_status` | التحذير |
|--------|--------------------|---------|
| لا سجل تحسن قراءة للطالب داخل نافذة الدورة | `missing` | لا يوجد سجل تحسن قراءة في جدول reading_improvements ضمن دورة الطالب. |

نافذة البحث تبدأ من تاريخ بداية الدورة وتنتهي عند `data_cutoff_at` إن وُجد، وإلا عند نهاية الدورة أو اللحظة الحالية أيهما أسبق. سجل خارج هذه النافذة لا يُحتسب حتى لو كان موجودًا.

### 8.3 معيار القرآن

| الحالة | `readiness_status` | التحذير |
|--------|--------------------|---------|
| لا حلقة تسميع أو تلقين لها أيام دوام في الفترات | `not_applicable` | — (لا يمنع الجاهزية) |
| الإنجاز دون الهدف ولم تُوضع الإشارة اليدوية | `missing` | الإنجاز المستخرج من سجلات التسميع دون الحد الأدنى؛ يلزم تأكيد «دون الحد الأدنى» فقط. |
| سجلات تسميع لا يمكن نسبتها إلى حلقة | `missing` | توجد سجلات تسميع قديمة لا يمكن نسبتها بدقة إلى حلقة؛ يجب ربطها بالحَلقة قبل الاعتماد. |

**حالة السجلات غير القابلة للنسب** هي أصعب حالات القرآن. تنشأ عندما يكون سجل التسميع بلا `circle_id` وبلا `course_id`، وللطالب أكثر من حلقة تسميع، أو أكثر من مدرس يطابق. الحل: ربط السجل بحلقته صراحةً في المصدر. معرفات السجلات المعلقة متاحة في `inputs.unresolved_source_record_ids`.

### 8.4 معيار الامتحانات النظرية

| الحالة | `readiness_status` | التحذير |
|--------|--------------------|---------|
| لا مواد نظرية مرتبطة بمقررات الطالب ولا نتائج | `not_applicable` | — |
| لا نتائج امتحانات معتمدة | `missing` | لا توجد نتائج امتحانات نظرية معتمدة. |
| مادة مطلوبة بلا نتيجة | `missing` | بعض المواد النظرية المطلوبة بلا نتيجة. |
| مادة درجتها العظمى صفر أو سالبة | `missing` | توجد نتيجة امتحان بدرجة عظمى غير صالحة. |

**الحالة الثالثة** ليست خطأ إدخال في التقييم بل خطأ إعداد في المادة: `subjects.max_marks` غير مضبوطة. القسمة على درجة عظمى صفرية تُعامل بصفر، والمعيار يبقى غير جاهز حتى تُصحَّح المادة.

### 8.5 معيار تقييم المدرس

| الحالة | `readiness_status` | التحذير |
|--------|--------------------|---------|
| نقص تقييم واحد لأي (فترة × حلقة) مطلوبة | `missing` | تقييم المدرس غير مكتمل لكل الفترات والحلقات المطلوبة. |

المطلوب هو الجداء الكامل: كل فترة تقييم × كل حلقة مسجل فيها الطالب. طالب في حلقتين ودورة من فترتين يحتاج **أربعة** تقييمات. التقييمات بحالة `draft` لا تُحتسب؛ يجب أن تكون `submitted` أو `approved`. المفاتيح الناقصة معدَّدة في `inputs.missing_keys` بصيغة `معرف_الفترة|معرف_الحلقة`.

### 8.6 معيار تقييم الإدارة ونقاط السبر

كلاهما جاهز دائمًا (`ready`)، ولا يمنعان الاحتساب:

- تقييم الإدارة يبدأ من الدرجة الكاملة ويُحسم منه بناءً على الإنذارات المسجلة والملاحظات المعتمدة غير المنقوضة.
- نقاط السبر مكافأة فوق المجموع الأساسي، تُمنح مرة واحدة لكل جزء لكل طالب مهما تكرر السبر.

## 9. المرحلة 6: الاحتساب

**المسار:** `POST /api/evaluation-cycles/{cycle}/runs`
**الصلاحية:** `احتساب النتائج النهائية`
**الشيفرة:** `EvaluationRunController::store` → `EvaluationRunService::run`

### 9.1 المعاينة مقابل الاحتساب النهائي

| | المعاينة (`preview = true`) | الاحتساب النهائي (`preview = false`) |
|---|---|---|
| يشترط حالة `ready` | لا | نعم |
| يشترط اكتمال الجاهزية | لا | نعم |
| يغيّر حالة الدورة | لا | نعم، إلى `calculated` |
| يثبّت `data_cutoff_at` | لا | نعم |

المعاينة أداة تشخيص متاحة في أي وقت؛ استخدمها لرؤية النتيجة المتوقعة قبل إغلاق جمع البيانات.

### 9.2 حالات الفشل

| السيناريو | HTTP | `error_code` | الرسالة |
|-----------|------|--------------|---------|
| حقل `preview` ناقص | 422 | `VALIDATION_FAILED` | يجب تحديد ما إذا كان الاحتساب معاينة أم احتسابًا نهائيًا. |
| احتساب نهائي والدورة ليست `ready` | 422 | `CYCLE_NOT_READY` | يجب إغلاق جمع البيانات ووضع الدورة في حالة «جاهزة» قبل الاحتساب النهائي. |
| تغيرت الحالة بين الفحص والقفل | 422 | `VALIDATION_FAILED` | يجب أن تكون الدورة جاهزة قبل الاحتساب النهائي. |
| مدخلات ناقصة عند لحظة الاحتساب | 422 | `VALIDATION_FAILED` | لا يمكن إنشاء نتيجة نهائية قبل اكتمال كل المدخلات. استخدم فحص الجاهزية لمعرفة النواقص. |
| المستخدم لا يدير الدورة | 403 | `FORBIDDEN` | ممنوع: لا تملك الصلاحيات المطلوبة لتنفيذ هذا الإجراء. |

**الفحص المزدوج مقصود:** الشرط يُفحص في المتحكم أولًا للاستجابة السريعة، ثم يُعاد فحصه داخل معاملة قاعدة البيانات بعد قفل صف الدورة (`lockForUpdate`). هذا يمنع سباق تشغيلين متزامنين ينتج عنهما تشغيلان نهائيان.

**أثر الفشل داخل المعاملة:** كل العملية تجري داخل معاملة واحدة. أي فشل — بما فيه فشل قاعدة البيانات — يرجع كل شيء: لا يبقى تشغيل معلق، ولا نتائج جزئية، ولا تتغير حالة الدورة.

## 12. المرحلة 9: إصدار الشهادات

**المسارات:** `POST /api/evaluation-results/{result}/certificate` (فردية) و`POST /api/evaluation-runs/{run}/certificates` (دفعة)
**الصلاحية:** `إصدار الشهادات النهائية`
**الشيفرة:** `CertificateService::issue`

| السيناريو | HTTP | `error_code` | الرسالة |
|-----------|------|--------------|---------|
| النتيجة غير منشورة | 422 | `VALIDATION_FAILED` | لا تصدر الشهادة إلا لنتيجة منشورة. |
| لا نتائج منشورة في التشغيل (دفعة) | 422 | `NO_PUBLISHED_RESULTS` | لا توجد نتائج منشورة في هذا التشغيل؛ يجب اعتماد النتائج ونشرها قبل إصدار الشهادات. |
| إصدار متزامن جارٍ منذ أقل من 10 دقائق | 422 | `VALIDATION_FAILED` | إصدار الشهادة قيد التنفيذ حاليًا. |
| محرك Chrome غير موجود أو غير قابل للتنفيذ | 503 | `SERVICE_UNAVAILABLE` | خدمة توليد الشهادات غير متاحة حاليًا؛ يرجى إبلاغ الفريق التقني ثم إعادة المحاولة. |
| فشل Chrome في توليد الملف | 500 | `SERVER_ERROR` | تعذر توليد ملف الشهادة. تم تسجيل التفاصيل الفنية للفريق التقني. |

### 12.1 السلوك عند التكرار والفشل

- **الطلب المكرر آمن:** إذا وُجدت شهادة سارية للنتيجة نفسها، تُعاد كما هي بلا إصدار جديد.
- **الإصدار المعلق:** سجل بحالة `generating` أقدم من عشر دقائق يُعتبر فاشلًا ويُعلَّم `failed`، فيُسمح بمحاولة جديدة. هذا يمنع قفل النتيجة إلى الأبد بعد انقطاع.
- **الفشل أثناء التوليد:** يُحذف الملف الجزئي من التخزين، وتُعلَّم الشهادة `failed`، ثم يُعاد رفع الاستثناء. لا تبقى شهادة نصف مكتملة.

### 12.2 حماية الرسائل الفنية

مخرجات Chrome عند الفشل نص فني طويل قد يتجاوز آلاف المحارف ويكشف مسارات ملفات الخادم. لذلك تُسجَّل في سجل الخادم تحت `error_code = CERTIFICATE_RENDER_FAILED` مع رمز الخروج ونص `stderr` كاملًا، بينما لا يصل المستخدم إلا الجملة العربية المختصرة.

| السيناريو | المسار | HTTP | `error_code` | الرسالة |
|-----------|--------|------|--------------|---------|
| الشهادة ملغاة أو استُبدلت | `GET /certificates/{id}/download` | 410 | `GONE` | هذه الشهادة لم تعد سارية؛ تم إلغاؤها أو استُبدلت بإصدار أحدث. |
| ملف الشهادة مفقود أو لا يطابق بصمته | التنزيل | 409 | `CONFLICT` | ملف الشهادة مفقود أو لا يطابق بصمته المحفوظة؛ يجب إلغاء الشهادة وإعادة إصدارها. |
| المستخدم لا يرى دورة الشهادة | التنزيل | 403 | `FORBIDDEN` | ممنوع: لا تملك الصلاحيات المطلوبة لتنفيذ هذا الإجراء. |
| رمز تحقق بصيغة غير صالحة | `GET /public/certificates/verify/{token}` | 404 | `NOT_FOUND` | رمز التحقق غير صالح أو لا يقابل شهادة سارية. |

| سبب الإلغاء أقصر من 5 أحرف | الإلغاء | 422 | `VALIDATION_FAILED` | سبب الإلغاء قصير جدًا؛ اكتب خمسة أحرف على الأقل. |

**توحيد رسالة التحقق مقصود:** حالتا «الصيغة خاطئة» و«لا شهادة مطابقة» تعيدان الرسالة نفسها، حتى لا يستدل مُهاجم على وجود رموز صالحة من اختلاف الرسائل.

**فشل بصمة الملف** ليس خطأ مستخدم بل مؤشر على تلف تخزين أو تعديل خارجي على الملف. يُسجَّل بالكامل تحت `CERTIFICATE_FILE_CORRUPT` مع معرف الشهادة ورقمها التسلسلي ومسار الملف، ويجب أن يُتابَع فنيًا لا أن يُتجاهل.

## 14. واجهة الطالب

**المسارات:** `GET /api/mobile/student/me/final-results` و`/{resultId}` و`GET /api/mobile/student/me/certificates/{certificateId}`

| السيناريو | HTTP | الرسالة |
|-----------|------|---------|
| نتيجة ليست للطالب نفسه | 404 | العنصر المطلوب غير موجود أو غير متاح لك. |
| نتيجة الطالب نفسه لكنها غير منشورة | 404 | العنصر المطلوب غير موجود أو غير متاح لك. |
| شهادة غير سارية أو ليست للطالب | 404 | العنصر المطلوب غير موجود أو غير متاح لك. |
| صلاحية الطالب غير ممنوحة لدوره | 403 | ممنوع: لا تملك الصلاحيات المطلوبة للوصول. |

**قرار أمني مقصود:** الوصول غير المصرح به إلى نتيجة طالب آخر يعود 404 لا 403. الفرق بين الرمزين يكشف وجود السجل من عدمه؛ توحيدهما على 404 يمنع تعداد المعرفات. لذلك «404» في واجهة الطالب لا تعني بالضرورة أن السجل غير موجود.

## 15. أخطاء الصلاحيات والنطاق

### 15.1 طبقتا الحماية

| الطبقة | الأداة | ما تفحصه | الرسالة |
|--------|--------|-----------|---------|
| الصلاحية | `permission:` middleware | هل يملك دور المستخدم هذه الصلاحية؟ | ممنوع: لا تملك الصلاحيات المطلوبة للوصول. |
| النطاق | `EvaluationAccessService` | هل هذه الدورة تحديدًا ضمن نطاقه؟ | ممنوع: لا تملك الصلاحيات المطلوبة لتنفيذ هذا الإجراء. |

اجتياز الطبقة الأولى لا يعني اجتياز الثانية. مدرس يملك صلاحية `إدخال تقييم المدرس` يُمنع من تقييم طالب ليس في حلقته.

### 15.2 مصفوفة النطاق

| الدور | يرى الدورة | يديرها | يعتمد وينشر | يقيّم طالبًا |
|-------|------------|--------|--------------|---------------|
| مدير النظام | نعم | نعم | نعم | نعم |
| مشرف العمليات الميدانية | نعم | نعم | نعم | نعم |
| مشرف المشروع | نعم | نعم | نعم | نعم |
| مشرف مقرر في الدورة | نعم | نعم | **لا** | نعم |
| مدرس حلقة في الدورة | نعم | لا | لا | لطلاب حلقته فقط |

**الحالة الأكثر إرباكًا:** مشرف مقرر يمكنه إدارة الدورة والاحتساب لكنه **لا يستطيع الاعتماد ولا النشر ولا إصدار الشهادات**. هذه المراحل محصورة بمشرف المشروع فما فوق. الرسالة نفسها في الحالتين، لذا راجع مصفوفة النطاق قبل افتراض عطل.

## 16. أخطاء قاعدة البيانات والأخطاء غير المتوقعة

### 16.1 خطأ قاعدة بيانات

| الجانب | التفصيل |
|--------|----------|
| HTTP | 500 |
| `error_code` | `DATABASE_ERROR` |
| الرسالة للمستخدم | تعذر إتمام العملية بسبب خطأ في قاعدة البيانات. لم يُحفظ أي تعديل، وسُجلت التفاصيل الفنية للفريق التقني. |
| ما يُسجَّل | نص الاستثناء، جملة SQL، رمز خطأ SQL، المسار، طريقة الطلب، اسم المسار، معرف المستخدم |
| ما لا يُرسل | جمل SQL، أسماء الجداول والأعمدة، القيم المرسلة، أثر الاستدعاء |

**سلامة البيانات:** كل عمليات الكتابة الحساسة — الاحتساب، الاعتماد، النشر، حفظ المدخلات، مزامنة المرشحين، إصدار الشهادة، تسوية إنجازات السبر — تجري داخل معاملات. فشل قاعدة البيانات يعني تراجعًا كاملًا. الجملة «لم يُحفظ أي تعديل» في الرسالة ليست طمأنة عامة بل وصف دقيق للسلوك.

### 16.2 خطأ غير متوقع

| الجانب | التفصيل |
|--------|----------|
| HTTP | 500 |
| `error_code` | `SERVER_ERROR` |
| الرسالة للمستخدم | حدث خطأ غير متوقع في الخادم. تم تسجيل التفاصيل الفنية وسيراجعها الفريق التقني. |
| في بيئة التطوير | يضاف مفتاح `debug` منفصل يحمل صنف الاستثناء ورسالته وموضعه — ولا يدخل حقل `message` أبدًا |

**ضمان مهم:** حتى مع `APP_DEBUG=true`، حقل `message` يبقى الجملة العربية العامة. تفاصيل المطور تسكن مفتاح `debug` منفصلًا لا تعرضه الواجهة. هذا يمنع تسرب تفاصيل بيئة التطوير إلى الشاشة، ويمنع اعتماد الواجهة على نص فني متغير.

### 16.3 حالات فنية أخرى

| السيناريو | HTTP | `error_code` | الرسالة |
|-----------|------|--------------|---------|
| انتهاء الجلسة أو رمز CSRF | 419 | `SESSION_EXPIRED` | انتهت صلاحية الجلسة؛ يرجى تحديث الصفحة وإعادة المحاولة. |
| تجاوز حد المحاولات | 429 | `TOO_MANY_REQUESTS` | عدد المحاولات كبير؛ يرجى الانتظار قليلاً ثم إعادة المحاولة. |
| طريقة HTTP خاطئة | 405 | `METHOD_NOT_ALLOWED` | طريقة الطلب غير مدعومة لهذا المسار. |
| النظام في وضع الصيانة | 503 | `SERVICE_UNAVAILABLE` | الخدمة متوقفة مؤقتًا للصيانة؛ يرجى المحاولة لاحقًا. |
| انقطاع الشبكة (يُكتشف في المتصفح) | — | — | تعذر الاتصال بخوادم النظام. يرجى التأكد من تشغيل السيرفر أو التحقق من الإنترنت. |

الحالة الأخيرة لا تصدر عن الخادم أصلًا؛ تولّدها طبقة الاتصال في الواجهة عند فشل الطلب قبل وصوله، وتظهر بالحالة `0`.

## 17. السجلات والمراقبة

كل خطأ فني يُسجَّل بسياق منظم يسمح بالتصفية والتنبيه:

| الحقل | المحتوى |
|-------|----------|
| `error_code` | رمز الخطأ نفسه المعاد للواجهة، لربط بلاغ المستخدم بسطر السجل |
| `exception` | صنف الاستثناء الكامل |
| `method` / `path` / `route` | الطلب الذي أنتج الخطأ |
| `user_id` | منفّذ الطلب، أو `null` إن لم يكن مصادقًا |
| `sql` / `sql_error_code` | في أخطاء قاعدة البيانات فقط |

أثر الاستدعاء الكامل يسجله الإطار في السطر نفسه؛ السياق أعلاه يضاف إليه ولا يكرره.

**رموز يُستحسن ضبط تنبيه عليها:**

| الرمز | الدلالة |
|-------|----------|
| `DATABASE_ERROR` | خلل في المخطط أو الاتصال؛ يوقف الاحتساب |
| `CERTIFICATE_FILE_CORRUPT` | تلف تخزين أو تعديل خارجي على ملفات الشهادات |
| `CERTIFICATE_ENGINE_UNAVAILABLE` | Chrome غير مثبت أو تغير مساره بعد نشر جديد |
| `CERTIFICATE_RENDER_FAILED` | فشل توليد متكرر؛ غالبًا نفاد ذاكرة أو صلاحيات ملفات |

سجل التدقيق منفصل عن سجل الأخطاء: `evaluation_audit_events` يوثق الإجراءات الناجحة الحساسة — إنشاء الدورة، تغيير حالتها، حفظ المدخلات، الاحتساب، الاعتماد، النشر، إصدار الشهادة وإلغاؤها — مع القيم قبل التعديل وبعده.

## 18. سلوك الواجهة الأمامية

**الملفات:** `src/lib/services/api.js`، `src/lib/services/apiErrors.js`، `src/lib/stores/toast.svelte.js`

| السلوك | التنفيذ |
|--------|----------|
| قراءة الرسالة | تُعرض `message` كما هي؛ الخادم يضمن أنها عربية وقصيرة |
| أخطاء الحقول | تُعرض من `errors` أسفل كل مدخل، مع `aria-invalid` و`role="alert"` |
| أخطاء متعددة في طلب واحد | تُدمج كل الرسائل في تنبيه واحد مفصولة بشرطة، فلا يدور المستخدم دورة لكل حقل |
| حمولة منظمة في `errors` | تُهمَل ولا تُعرض، فلا يظهر `[object Object]` في تنبيه |
| مدة التنبيه | أخطاء 8 ثوانٍ بدل 4، لأن رسالة الخطأ تحمل السبب والحل |
| رفض إغلاق جمع البيانات | تُحدَّث لوحة الجاهزية من `data.readiness` فورًا |
| انتهاء الجلسة (401) | تُمسح الجلسة ويُوجَّه المستخدم إلى صفحة الدخول |
| انتهاء رمز CSRF (419) | يُجدَّد الرمز ويُعاد الطلب مرة واحدة تلقائيًا |
| فشل الشبكة | رسالة اتصال واضحة بالحالة `0` |
| تنزيل الشهادة | رسالة الخطأ تُقرأ من حمولة JSON حتى لو كان الطلب طلب ملف |

**قاعدة للمطورين:** المعالجة البرمجية تُبنى على `error_code` لا على نص `message`. نص الرسالة قابل للتحسين اللغوي في أي وقت، أما الرمز فعقد ثابت.

## 19. قائمة تحقق سريعة: «لماذا لا يكتمل التقييم؟»

اتبع الترتيب؛ كل سؤال يفترض نجاح ما قبله.

1. **هل الدورة تحوي مرشحين نشطين؟** لا → نفّذ مزامنة المرشحين. دورة بلا مرشحين ليست جاهزة أبدًا.
2. **هل حالة الدورة `data_collection`؟** لا → المدخلات مقفلة. الانتقال إلى `data_collection` مرفوض قبل انتهاء آخر فترة.
3. **هل فحص الجاهزية يعيد `is_ready = true`؟** لا → افتح لقطة الجاهزية واقرأ المعايير `missing` لكل طالب.
4. **هل الحضور ناقص؟** الجلسات المفقودة معدَّدة في `inputs.missing_sessions` — تُصلَح في مصدر الحضور لا في شاشة التقييم.
5. **هل تقييم المدرس ناقص؟** المطلوب كل فترة × كل حلقة. راجع `inputs.missing_keys`، وتأكد أن الحالة `submitted` لا `draft`.
6. **هل القرآن ناقص؟** إما إشارة «دون الحد الأدنى» غير موضوعة، أو سجلات تسميع غير قابلة للنسب في `inputs.unresolved_source_record_ids`.
7. **هل القراءة ناقصة؟** لا سجل تحسن داخل نافذة الدورة. تحقق من وقوع تاريخ السجل داخل النافذة.
8. **هل الامتحانات ناقصة؟** إما لا نتائج، أو مادة بلا نتيجة، أو `subjects.max_marks` غير مضبوطة.
9. **هل الاحتساب النهائي مرفوض؟** الدورة يجب أن تكون `ready`. أغلق جمع البيانات أولًا.
10. **هل الاعتماد مرفوض؟** التشغيل يجب أن يكون نهائيًا (لا معاينة) وحالته `completed`، والمنفّذ مشرف المشروع فما فوق.
11. **هل النشر مرفوض؟** الدورة يجب أن تكون `approved`.
12. **هل إصدار الشهادات مرفوض؟** النتائج يجب أن تكون `published`، ومحرك Chrome يجب أن يكون متاحًا على الخادم.
13. **هل تظهر رسالة 500؟** ليست خطأ إجرائيًا. ابحث في سجل الخادم بـ `error_code` وسلّم السطر للفريق التقني.
